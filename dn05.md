# Design Note 05

# What Exactly Is a Cryptographic Asset?

> "You cannot inventory something unless you first define what counts as an asset."

---

# The Word "Asset"

Imagine someone asks,

> "Make an inventory of all company assets."

What comes to mind?

Probably

- laptops
- servers
- monitors
- routers
- buildings

These are physical assets.

Now imagine someone asks instead,

> "Inventory every cryptographic asset."

The answer is much less obvious.

Most people immediately think

> "RSA."

But RSA is only one example.

The real answer is much broader.

---

# What Is A Cryptographic Asset?

A cryptographic asset is **anything that contributes to the security of a cryptographic system.**

Notice the wording.

It doesn't have to be an algorithm.

It doesn't even have to be code.

If removing that object weakens or changes the security of the system,

it is likely a cryptographic asset.

---

# Think Like A Mechanic

Imagine inspecting a car.

You don't only inspect the engine.

You inspect

- brakes
- tires
- gearbox
- battery
- steering
- suspension

Each component contributes to the car.

Cryptography works the same way.

RSA is only one component.

A secure system contains many different cryptographic assets working together.

---

# Examples

Let's look at a normal web server.

```
Client

↓
```

Which of these are cryptographic assets?

The answer is...

# Categories of Cryptographic Assets

Instead of memorizing individual examples,

it's better to think in categories.

---

## 1. Algorithms

Examples

- RSA
- ECC
- AES
- ChaCha20
- SHA-256
- HMAC
- ML-KEM
- ML-DSA

Algorithms describe *what mathematics* is being used.

---

## 2. Keys

Keys are among the most valuable cryptographic assets.

Examples

```
Private Key

Public Key

AES Key

API Signing Key

JWT Signing Key

SSH Private Key

VPN Key
```

Without keys,

algorithms are useless.

---

## 3. Certificates

Certificates connect identities to public keys.

Examples

```
TLS Certificate

Root Certificate

Intermediate Certificate

Client Certificate
```

Certificates expire.

Certificates rotate.

Certificates can become compromised.

Organizations often possess thousands of them.

---

## 4. Protocols

Protocols define *how* cryptography is used.

Examples

```
TLS

SSH

IPsec

WireGuard

HTTPS

S/MIME
```

The algorithm might be secure,

yet the protocol configuration could still be weak.

---

## 5. Libraries

Very little software implements cryptography from scratch.

Instead,

developers depend on libraries.

Examples

```
OpenSSL

BoringSSL

LibreSSL

libsodium

wolfSSL

mbedTLS

Java Cryptography Architecture
```

These libraries themselves become important assets.

---

## 6. Hardware

Some cryptographic secrets never leave dedicated hardware.

Examples

```
Hardware Security Module (HSM)

Trusted Platform Module (TPM)

Smart Cards

Secure Enclave

YubiKey
```

Hardware matters just as much as software.

---

## 7. Configuration

Sometimes

nothing is wrong with the algorithm.

The problem is simply configuration.

Example

```
AES

Mode

↓

ECB
```

AES itself is strong.

AES-ECB is generally considered a poor choice because it reveals patterns.

Likewise

```
TLS 1.0

SSLv3

Weak Cipher Suites
```

Configuration matters.

---

# What About Source Code?

Consider this Java code.

```java
Cipher.getInstance("AES/CBC/PKCS5Padding");
```

What are the assets?

Not the file.

Not the class.

The assets are

```
AES

CBC

PKCS5Padding
```

Notice something.

Carcinus is not interested in Java.

It is interested in the cryptographic information hidden inside Java.

The programming language is merely where the asset happens to be found.

---

# Another Example

Rust.

```rust
let key = RsaPrivateKey::new(...);
```

Again,

the scanner does not care that this is Rust.

It extracts

```
RSA

Private Key
```

Everything else becomes irrelevant.

---

# One More Example

OpenSSL configuration.

```
CipherString = DEFAULT:@SECLEVEL=1
```

Again,

the file itself is not important.

The important information is

```
Cipher Suite

Security Level

Configuration
```

---

# The Scanner's Job

This leads us to an important realization.

The scanner is **not** trying to understand the entire project.

That would be impossible.

Instead,

it asks a much simpler question.

```
Does this file contain any cryptographic assets?
```

If yes,

extract them.

Ignore everything else.

---

# Normalization

Imagine these three files.

Java

```java
Cipher.getInstance("AES")
```

Python

```python
AES.new(...)
```

Rust

```rust
Aes256::new(...)
```

Different languages.

Different syntax.

Different libraries.

Different APIs.

Yet,

they all describe essentially the same thing.

```
Algorithm

↓

AES
```

Carcinus should not produce three different outputs.

Instead,

it converts everything into one common representation.

We call this process

**Normalization.**

---

# Why Normalization Matters

Imagine supporting

20 programming languages.

Without normalization,

the Risk Engine must understand

Java.

Python.

Rust.

Go.

C.

C++.

JavaScript.

C#.

PHP.

...

Eventually,

every component depends on every language.

The architecture becomes impossible to maintain.

Instead,

the discovery layer performs the translation once.

Everything after that only consumes normalized artifacts.

```
Java

↓

Python

↓

Rust

↓

Go

↓

Normalization

↓

Artifact

↓

Risk Engine

↓

Recommendation Engine

↓

Dashboard
```

Notice something beautiful.

The Risk Engine no longer knows

or cares

where the artifact came from.

That is good architecture.

---

# What Does One Artifact Look Like?

Carcinus might internally represent every discovery like this.

```yaml
type: Algorithm

name: RSA

version: RSA-2048

location:
  repo: auth-service
  file: auth.java
  line: 42

confidence: High

source: Static Analysis

language: Java
```

Or

```yaml
type: Certificate

issuer: DigiCert

expires: 2027-04-19

algorithm: RSA

key_length: 2048
```

Notice how

Java,

Python,

OpenSSL,

Docker,

and Kubernetes

all eventually produce

the same language-independent objects.

This is one of the most important architectural decisions in Carcinus.

---

# Engineering Discussion

A common beginner mistake is thinking

"Our scanner supports Java."

No.

That's not the goal.

A mature scanner supports

Artifacts.

Java is simply one of many ways those artifacts can appear.

This distinction seems subtle.

It completely changes the architecture.

---

# Connecting This To SIH

Let's read the first line of the deliverables.

> Scan source code repositories.

Now think about what we've learned.

Repositories contain

files.

Files contain

syntax.

Syntax contains

cryptographic assets.

Those assets become

normalized artifacts.

Those artifacts eventually become

the Cryptographic Bill of Materials.

Everything after that—

risk assessment,

recommendations,

migration planning—

depends on those normalized artifacts.

This is why discovery is the foundation of the entire project.

---

# Things To Remember

• A cryptographic asset is anything that contributes to cryptographic security.

• Assets include algorithms, keys, certificates, protocols, libraries, hardware, and configurations.

• Carcinus discovers assets—not programming languages.

• Programming languages are merely containers for assets.

• The discovery engine extracts cryptographic information.

• The normalization layer converts discoveries into a common format.

• Every downstream component consumes normalized artifacts.

• Good architecture isolates language-specific logic from business logic.

• The CBOM is built from normalized artifacts.
