# Design Note 01

# A Crash Course in Cryptography

> "Before we can understand why Post-Quantum Cryptography matters, we first need to understand what today's cryptography is actually doing."

---

# The Word "Cryptography"

If someone asks,

> "What is cryptography?"

Most people answer,

> "Encryption."

That's only part of the story.

Cryptography is the science of protecting information.

It allows computers to answer four very important questions.

---

# Question 1

## Can someone else read my data?

Imagine sending your friend a WhatsApp message.

Without protection, anyone sitting between you and WhatsApp could read it.

Your Internet Service Provider.

A malicious Wi-Fi hotspot.

An attacker.

Anyone.

Encryption prevents this.

Only someone possessing the correct key can recover the original message.

This property is called

**Confidentiality**

---

# Question 2

## Has someone changed my data?

Imagine downloading Ubuntu.

The website says

```
ubuntu.iso
```

You download it.

Now imagine an attacker secretly replaced it with malware.

How would you know?

The file still has the same name.

It might even be the same size.

Cryptography solves this using hashes and digital signatures.

They allow software to detect modifications.

This property is called

**Integrity**

---

# Question 3

## Who actually sent this?

Suppose you receive an email.

It says

> Transfer ₹50,00,000 immediately.

It claims to come from your CEO.

Did it?

Or is someone pretending?

Authentication allows us to verify identity.

Examples include

- Passwords
- SSH Keys
- TLS Certificates
- Digital Signatures

This property is called

**Authentication**

---

# Question 4

## Can the sender deny sending it later?

Imagine signing a legal document digitally.

A week later the sender claims

> "I never signed that."

Digital signatures help prevent this.

This property is called

**Non-Repudiation**

---

# The Four Goals

Modern cryptography mainly exists to provide these guarantees.

```
Confidentiality

↓

Integrity

↓

Authentication

↓

Non-Repudiation
```

Almost every cryptographic system provides one or more of them.

# Cryptography Is Not One Thing

One common misconception is

> "Cryptography" is a single technology.

It isn't.

It is an entire ecosystem.

Imagine medicine.

Medicine includes

- surgery
- cardiology
- neurology
- pediatrics

Similarly, cryptography includes

- encryption
- hashing
- signatures
- key exchange
- authentication
- certificates

Each solves a different problem.

# Symmetric Encryption

Imagine two friends.

Alice

and

Bob.

Both already possess the same secret key.

Alice encrypts a message.

Bob decrypts it.

The same key performs both operations.

```
Message

↓

AES

↓

Ciphertext

↓

AES

↓

Original Message
```

Examples include

AES

ChaCha20

DES (legacy)

These algorithms are extremely fast.

They protect large amounts of data.

---

# The Problem

Question.

How do Alice and Bob obtain the same key?

They need to exchange it somehow.

But...

if they already have a secure channel...

why did they need encryption?

This is known as

**The Key Distribution Problem**

For decades, this was one of the biggest challenges in cryptography.

The solution eventually led to...

Public Key Cryptography.

We will study that in the next design note.

# Hash Functions

Hashes are different from encryption.

Encryption is reversible.

Hashes are not.

Imagine placing a document into a machine.

```
Document

↓

SHA-256

↓

A1B93F4D...
```

A tiny change in the document completely changes the output.

Even changing

```
Hello
```

to

```
hello
```

produces a completely different hash.

Hashes are mainly used to verify integrity.

---

# Example

Ubuntu publishes

```
ubuntu.iso

SHA256

4f29b8...
```

After downloading,

your computer computes the hash again.

If both hashes match,

the file was almost certainly not modified.

If they differ,

the download has been corrupted or tampered with.

---

# Digital Signatures

Suppose Ubuntu publishes

```
ubuntu.iso
```

An attacker could also replace the published hash.

How do we trust the hash itself?

This is where digital signatures come in.

The publisher signs the hash.

Your computer verifies the signature.

Now an attacker cannot simply replace both files.

Digital signatures provide

- authenticity
- integrity

They are everywhere.

Software updates.

Git commits.

PDF signing.

Code signing.

Package repositories.

Government documents.

---

# Certificates

Suppose you visit

```
https://google.com
```

How do you know it is really Google?

Anyone can create a website that looks identical.

Your browser checks a

TLS Certificate.

That certificate says,

> "A trusted authority verified that this server belongs to Google."

Certificates rely heavily on cryptography.

They are one of the most important assets Carcinus will eventually discover.

---

# Keys

Almost every cryptographic system depends on keys.

Think of a key exactly like a physical house key.

Without it,

encrypted data is useless.

Organizations often manage

thousands

or even

millions

of cryptographic keys.

Some expire.

Some rotate automatically.

Some are forgotten.

Some are hardcoded into source code.

Managing keys is one of the hardest parts of enterprise security.

---

# Engineering Discussion

Imagine removing every cryptographic object from a company.

No passwords.

No HTTPS.

No SSH.

No VPN.

No certificates.

No encrypted databases.

No secure updates.

The company would still have software.

But it could no longer trust anything.

Modern computing depends upon trust.

Cryptography provides that trust.

# Why This Matters For Carcinus

Notice something.

So far,

we have discussed

Encryption

Hashes

Certificates

Keys

Digital Signatures

Algorithms

Protocols

Each of these is different.

Yet...

every one of them is a

**Cryptographic Asset.**

Carcinus is not looking for "encryption."

It is looking for

every cryptographic asset

inside an organization.

Understanding those assets is the first step toward building a Cryptographic Bill of Materials.

# Things To Remember

• Cryptography is much more than encryption.

• Modern cryptography mainly provides:
  - Confidentiality
  - Integrity
  - Authentication
  - Non-Repudiation

• Encryption protects secrecy.

• Hashes detect modification.

• Digital signatures verify authenticity.

• Certificates establish identity.

• Keys are the foundation of almost every cryptographic system.

• Organizations depend on thousands of cryptographic assets.

• Discovering those assets is the first challenge Carcinus aims to solve.
