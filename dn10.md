# Design Note 10

# The Recommendation Engine: Turning Analysis into Action

> "Finding problems is only half the job.
>
> A good engineering system should also help solve them."

---

# What The Risk Engine Produces

Suppose the Risk Engine reports

```
Repository

payments-service

Findings

RSA-1024

TLS 1.0

Certificate expires in 18 days

Overall Risk

High
```

This is already useful.

But imagine giving this report to a project manager.

Their next question is obvious.

> "What exactly should my team do?"

That is the responsibility of the Recommendation Engine.

---

# From Facts To Decisions

Think of the pipeline.

```
Discovery

↓

Facts

↓

Risk Engine

↓

Problems

↓

Recommendation Engine

↓

Actions
```

Each stage moves one step closer to helping people make decisions.

---

# Recommendations Are Rules

For the MVP,

recommendations do not require AI.

Suppose the Risk Engine produces

```
Algorithm

RSA
```

The Recommendation Engine simply looks up

```
RSA

↓

Migration Guidance
```

Example output

```
Current

RSA-2048

Recommendation

Begin planning migration to hybrid ML-KEM deployment when ecosystem support is available.
```

Notice something.

The Recommendation Engine is not inventing advice.

It is applying engineering knowledge.

---

# Another Example


completely deterministic.

# Recommendation Templates

Instead of generating recommendations dynamically,

Carcinus can maintain a structured knowledge base.

Example.

```yaml
Rule

RSA

Recommendation

Plan migration toward PQC-compatible key exchange.

Reference

NIST Guidance

Priority

High
```

Another.

```yaml
Rule

TLS 1.0

Recommendation

Upgrade to TLS 1.3.

Priority

High
```

This makes recommendations

consistent,

reviewable,

and explainable.

---

# Why Templates Matter

Suppose 100 repositories contain RSA.

Should they receive

100 slightly different AI-generated explanations?

Probably not.

Engineers value consistency.

If two systems have the same problem,

they should receive the same recommendation.

Templates provide that consistency.

---

# Prioritization

Not every recommendation deserves equal attention.

Imagine

Repository A

```
RSA-2048

Internal Test Server
```

Repository B

```
RSA-2048

Public Banking API
```

The recommendation is technically identical.

The priority is not.

Business context changes urgency.

# Recommendation Categories

Carcinus should classify recommendations.

For example

```
Immediate

↓

Soon

↓

Planned

↓

Monitor
```

Or

```
Critical

High

Medium

Low
```

---

# Explainability

Every recommendation should answer three questions.

---

## Why?

```
RSA relies on mathematical assumptions expected to become vulnerable to sufficiently capable quantum computers.
```

---

## What?

```
Plan migration toward standardized Post-Quantum algorithms.
```

---

## When?

```
Medium Priority

Migration should begin during upcoming infrastructure modernization.
```

Good recommendations always explain themselves.

---

# Recommendations Are Independent

Notice something important.

The Recommendation Engine never sees source code.

It only consumes findings.

```
Risk Finding

↓

Recommendation

↓

Report
```

This makes it independent of programming languages,

parsers,

and repositories.

---

# Executive Recommendations

Different audiences require different outputs.

Security engineers may want

```
Repository

↓

File

↓

Line Number

↓

Evidence
```

Executives may only care about

```
17 High Risk Assets

↓

5 Critical Systems

↓

Estimated Migration Effort

↓

Overall Readiness Score
```

Both reports originate from exactly the same recommendations.

Only the presentation differs.

---

# Why AI Might Help Later

Earlier,

we deliberately avoided AI in the Risk Engine.

Here,

AI becomes more reasonable.

Example.

Instead of showing

```
RSA detected

Recommendation

Hybrid ML-KEM Migration
```

an LLM could generate

```
This repository currently depends on RSA for key exchange. While RSA remains secure against classical attacks, organizations should begin planning migration toward standardized post-quantum hybrid deployments. This repository is ranked Medium Priority because it is internally hosted and processes short-lived data.
```

Notice something.

The AI is **summarizing existing knowledge**.

It is not deciding what is secure.

That distinction is very important.

# Engineering Discussion

Many security tools stop after identifying problems.

They produce

```
547 Findings
```

and leave the user to figure out everything else.

Carcinus should go one step further.

It should answer

> "What should the organization do next?"

This transforms the platform from a scanner into a decision-support system.

---

# Things To Remember

• Recommendations transform findings into actions.

• The MVP can use deterministic rule templates.

• Consistency is more valuable than creativity.

• Business context determines priority.

• Different audiences need different report formats.

• AI is optional and belongs after analysis, not before it.

• The Recommendation Engine consumes findings, not source code.

• Reports are generated from recommendations.

• Carcinus aims to support decisions, not just detection.
